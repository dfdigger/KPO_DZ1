#  Zoo Management Console App

## Основная идея решения
1. Пользователь взаимодействует с консолью, вводя данные о животном 
2. Ветклиника (`VetClinic`) проверяет здоровье животного  
3. Зоопарк (`Zoo`) принимает или отклоняет животное в зависимости от результата проверки
4. Все основные компоненты внедряются через **DI-контейнер** (`Microsoft.Extensions.DependencyInjection`)
5. Приложение работает в цикле, позволяя добавлять несколько животных за одну сессию

## Применение принципов SOLID

| Принцип | Применение в проекте |
|----------|----------------------|
| **S — Single Responsibility Principle**<br> | Каждый класс выполняет одну задачу:<br>`Zoo` управляет коллекцией животных,<br>`VetClinic` проверяет здоровье,<br>`Animal` описывает сущность животного |
| **O — Open/Closed Principle**<br> | Система легко расширяется новыми типами животных (например, `Elephant`, `Lion`), не изменяя существующий код. Достаточно добавить новый класс-наследник `Animal` |
| **L — Liskov Substitution Principle**<br> | Все наследники `Animal` могут использоваться вместо базового `IAnimal` без нарушения работы программы |
| **I — Interface Segregation Principle**<br> | Интерфейсы чётко разделены по зонам ответственности: `IAnimal`, `IVetClinic`, `IZoo` — каждый описывает только нужное поведение |
| **D — Dependency Inversion Principle**<br> | Классы не создают зависимости напрямую (`new`), а получают их через DI-контейнер
